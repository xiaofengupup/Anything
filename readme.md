# 设计模式
## 发布订阅模式（Publish-Subscribe Pattern）

发布订阅模式是一种典型的消息通信设计模式，用于实现模块之间的**解耦通信**。其核心思想是发布者（Publisher）不直接依赖订阅者（Subscriber），而是通过统一的消息中心（PubSubCenter）完成消息的发布与分发。

### 核心组件

- **Publisher（发布者）**：负责向指定 Topic 发布消息，无需关心消息由谁接收。
- **PubSubCenter（消息中心）**：负责维护 Topic 与 Subscriber 之间的订阅关系，并根据 Topic 将消息分发给对应的订阅者。
- **Subscriber（订阅者）**：根据业务需求订阅指定 Topic，并注册回调函数，用于处理接收到的消息。

### 核心工作流程

1. Subscriber 向 PubSubCenter 注册订阅主题及对应的回调函数。
2. PubSubCenter 保存 Topic 与回调函数之间的映射关系。
3. Publisher 向 PubSubCenter 发布指定 Topic 的消息。
4. PubSubCenter 根据 Topic 查找所有订阅者，并依次调用对应的回调函数。
5. Subscriber 通过回调函数接收并处理消息，也可以主动取消订阅。

### C++ 实现要点

- 使用 `std::function` 统一封装普通函数、Lambda 表达式及成员函数回调。
- 使用 `std::unordered_map<Topic, std::vector<Subscription>>` 管理主题与订阅关系。
- 使用唯一的 `Subscription ID` 标识订阅关系，支持精准取消订阅。
- 使用 `std::weak_ptr` 配合 Lambda 管理订阅者生命周期，避免悬空指针。

### 设计优势

- **低耦合**：发布者与订阅者无需直接依赖。
- **可扩展**：支持多个发布者和多个订阅者。
- **灵活性高**：支持动态订阅和取消订阅。
- **易维护**：通过统一消息中心管理消息通信，降低模块间的依赖关系。

该模式适用于模块间事件通知、状态同步、消息分发以及异步事件处理等场景。

## 观察者模式（Observer Pattern）

观察者模式是一种行为型设计模式，用于建立对象之间的一对多依赖关系。当被观察者（Subject）的状态发生变化时，会自动通知所有注册的观察者（Observer），使观察者能够及时响应状态变化。

### 核心组件

- **Subject（被观察者）**：维护观察者列表，提供注册、移除和通知观察者的接口。
- **Observer（观察者）**：定义统一的更新接口，用于接收被观察者发送的状态变化通知。
- **ConcreteSubject（具体被观察者）**：维护自身状态，在状态发生变化时通知所有观察者。
- **ConcreteObserver（具体观察者）**：实现观察者接口，根据收到的通知执行相应的业务逻辑。

### 核心工作流程

1. Observer 向 Subject 注册，建立观察关系。
2. Subject 维护所有已注册的 Observer。
3. 当 Subject 的状态发生变化时，调用通知接口。
4. Subject 遍历观察者列表，依次调用 Observer 的更新接口。
5. Observer 接收到通知后，根据业务需求执行相应操作，也可以主动取消注册。

### C++ 实现要点

- 使用抽象基类和虚函数定义统一的 Observer 通知接口。
- 使用 `std::vector` 或 `std::unordered_map` 管理观察者对象。
- 使用智能指针管理观察者生命周期，避免悬空指针。
- 通过注册和注销机制动态维护观察关系。

### 设计优势

- **低耦合**：被观察者不需要了解具体观察者的业务实现。
- **动态扩展**：支持运行时动态添加和移除观察者。
- **自动通知**：状态变化时自动触发通知机制。
- **职责清晰**：状态维护与状态响应分别由不同对象负责。

观察者模式适用于 GUI 事件通知、对象状态监听、配置变化通知以及模块间状态联动等场景。
